# 1500-worker exact planner optimization

This records the optimization verification before release packaging and local
installation. For subsequent publication/package status, see the
[0.3.4 release record](../releases/v0.3.4-performance-preview.md).

## Current Result

Increment13 meets the timing target in all seven 1500-worker cases in each of
three fresh commandlet processes: 1.843805 to 4.906275 seconds host wall time.
All six original objective checks and assignment hashes pass; the additional
fractional case matches the eager reference's assignment, objective and solver
state bits. The exact algorithm and assignment policies are retained.

The final registered 89-script regression suite passes with zero failures.
Both saved production assets are byte-identical before and after the suite,
and those exact assets are synchronized to the source worktree. The approved
benchmark target is achieved. This optimization verification did not install
or publish a package.
The chronological sections below retain earlier failures and superseded timings.

## Acceptance

The approved target is below 5.0 seconds for planner computation with 1500
workers, without replacing the exact planner with a hybrid or approximation.
World snapshot/scoring, teacher-profile search, game-frame scheduling and applying
assignments are separate phases and are not included in this target. No release
or installed game package is changed by this work.

The six-case compiled benchmark includes StartPlan, RequireFixedSlots with all
slots unpinned (the real search pipeline always configures this), KeepUnassigned,
AdvancePlan, observation and result checks. Fixture generation and editor startup
are excluded. Acceptance uses host wall time, not only accumulated compiled calls.
All candidate timings must retain objective checks and assignment hashes.

## Exact Integer-MinV Candidate

worker prefix. It does not replace the Hungarian algorithm, objective, tie
rules or feasibility constraints. A complete ordinary scan certifies the final
unused labels within +/-2^50 and collects a real-prefix upper bound and a dummy
lower bound. Partial scans cannot certify the representation. The witness can
be reacquired after a complete ordinary fallback scan within the same root.

Raw labels share an independently bounded exact offset. Birth epochs and zero
payloads preserve signed zero, including a nonzero epoch whose net offset is
zero. Dummies remain eager. A strictly separated real/dummy domain certifies
unchanged ordering for the existing native sort/find; scalar consumers decode
the actual label. Both signs of Delta update a separate conservative dummy
lower bound in the original arithmetic order. Existing dummy-skip bounds are
unchanged.

The constant-time real-prefix potential step requires the existing U/V integer
certificate, no free real column, no Used dummy, and the domain proof. The last
live real index is maintained by a bounded monotone scan. It preserves the
original NativeValue scratch result and V[0] update. Materialization is bounded
and precedes augmentation, ordinary fallback, U/V fallback or an invalid label
write. Cancellation is inert and initialization clears every private field.

## Useful-Scan Gate

The strict-priority regression is addressed first with a narrow exact guard.
FirstFreeColumn is set by initialization or state10 and positive P entries
change only in state7. During an augmentation, FirstFreeColumn therefore cannot
cross the real-worker-prefix boundary. IntegerMinPrepare already rejects a
