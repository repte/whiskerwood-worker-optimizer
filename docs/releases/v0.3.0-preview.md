# Worker Optimizer 0.3.0-preview

**One manual assignment icon, with minimum crews before best-fit extra staffing.**

Preview for **Whiskerwood 0.7.209.0 on Windows**. **In-game validation is pending and will be performed by the user.** Earlier release tests do not validate this package.

## Changes

- Only the manual assignment icon is exposed. The settings gear, logbook button and former panels are inaccessible.
- The icon remains visible; the former visibility shortcut and older saved bindings are disabled.
- Automatic schedules are disabled, including schedules saved by earlier versions. Loading a save or reaching a new day does not start assignment.
- All active supported buildings use the same priority. Saved category priorities, building-type overrides and strict/weighted mode choices are ignored.
- The saved builder reserve is still respected, defaulting to one when unset. This preview has no reserve editor.
- Feasible minimum operating crews are considered before additional positions are filled by worker suitability. Eligibility, protected workplaces and the reserve still constrain staffing.
- Moves account for each target's native dependencies instead of firing workers across the settlement in one global batch.
- Replacing a required worker also causes the game to dismiss that building's optional workers. The queue explicitly releases movable optional workers first and schedules their planned assignments afterward. Required incumbents stay fixed where a change would dismiss a protected optional occupant. Other unchanged assignments remain in place.
- Native assignment request handling has been revised. Acceptance by the shipping game still needs testing and is not guaranteed.

The old settings and logbook implementation remains in the source and assets, with its views inaccessible. Existing saved preferences and history are not deleted. Visibility shortcuts are disabled in this preview.

## Download and Install

Download **WorkerOptimizer-v0.3.0-preview.zip**, not GitHub's source-code archives. Close the game and extract its `WorkerOptimizer` folder into:

```text
%LOCALAPPDATA%\Whiskerwood\Saved\mods\
```

The folder must contain `WorkerOptimizer.pak` and `WorkerOptimizer.uplugin`. No Python or Unreal Editor is needed. Use a local installation or a Workshop subscription, not both.

The Workshop upload is prepared separately for the existing item. **It is not submitted by this release workflow.** Publishing this GitHub preview does not update the live Workshop item.

## Validation and Limits

The complete automated Blueprint suite, full Windows cook and package validation passed on **7 October 2026 (CEST)**. The verified PAK contains **46 runtime assets** and no editor/test helpers. The user's in-game test is pending; editor fixtures cannot prove shipping-game behavior because the modkit contains native-function stubs. See [verification details](https://github.com/repte/whiskerwood-worker-optimizer/blob/v0.3.0-preview/docs/verification/2026-10-07-manual-core.md).

PAK SHA-256: `3A205A5922F545AD9DBD9E4E33BCB475FFC743AA2AC4A96BF0DC202FB907C5CD`.

Use a separate test save. Verify the single icon, disabled schedules from old saves, ignored old priority/mode choices, preserved reserve, minimum-crew coverage and the actual workers shown in the game's building windows. Earlier UI screenshots and successful runs belong to older versions.

The icon shows its busy state until the request completes. Extra clicks do not restart or cancel it. Supported native assignment effects are checked immediately after each call returns, and only observed effects count as confirmed changes. A returned failure does not leave a persistent lock; another manual attempt is possible after result processing. Unrelated later changes are not counted as late success. Confirmed changes are not automatically rolled back. Scarce or ineligible workers can leave workplaces unstaffed even when all buildings have equal priority.

Large-settlement performance, complex school arrangements, extended sessions, all-language presentation and interactions with other mods need broader testing. The preview does not promise that every assignment request succeeds.
