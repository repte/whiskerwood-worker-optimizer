# v0.3.4-performance-preview

Exact large-settlement planner performance preview for **Whiskerwood 0.7.209.0
on Windows**. **In-game acceptance of this version remains pending.** Workshop
publication is separate and is not performed by this GitHub release.

[GitHub release](https://github.com/repte/whiskerwood-worker-optimizer/releases/tag/v0.3.4-performance-preview) |
[Packaged ZIP](https://github.com/repte/whiskerwood-worker-optimizer/releases/download/v0.3.4-performance-preview/WorkerOptimizer-v0.3.4-performance-preview.zip)

## Changes

- Retain the existing exact assignment approach, without a hybrid, greedy or
  approximate replacement.
- Reduce repeated matrix validation, equivalent row work, label updates and
  coordinator calls. Optimizations use exact guards and preserve the original
  calculation when their conditions do not hold.
- Preserve minimum crews, worker eligibility, protected occupants, builder
  reserve, teacher-dependent planning and the existing gameplay-only icon.
- Keep the public manual interface and its equal building priorities unchanged.

## Measured Performance

Seven **1,500-worker** cases were run in **three fresh commandlet processes**
on the test machine (Intel Core i7-12700K). All 21 candidate measurements were
below five seconds: **1.84-4.91 seconds of host planner time**.

| Case | Run 1 | Run 2 | Run 3 |
| --- | ---: | ---: | ---: |
| Equal builders, reserve 1 | 1.849 s | 1.951 s | 1.844 s |
| Equal builders, reserve 3 | 1.946 s | 2.053 s | 1.960 s |
| Varied builders, reserve 3 | 4.424 s | 4.649 s | 4.360 s |
| Tied scores, varied builders | 2.994 s | 3.050 s | 2.851 s |
| Mixed priorities, strict | 4.864 s | 4.749 s | 4.702 s |
| Mixed priorities, weighted | 2.537 s | 2.603 s | 2.390 s |
| Additional fractional case | 4.765 s | 4.906 s | 4.661 s |

All six original objective checks and assignment hashes remain unchanged. The
additional fractional case matches the eager reference's assignment, objective
and solver-state bits. Mixed priorities are internal regression cases; the
public manual interface continues to use equal building priorities.

Timing includes planner initialization, configuration, compiled planning calls
and host observation/result checks. It excludes fixture construction, editor
startup, settlement capture, scoring, school search, frame scheduling and
application. These are compiled commandlet measurements, **not shipping-game
end-to-end times or a guarantee for every computer or settlement**. The slowest
run has about 94 ms headroom. Complex school combinations can still be costly.

See the [complete measurement and correctness record](https://github.com/repte/whiskerwood-worker-optimizer/blob/v0.3.4-performance-preview/docs/verification/2026-10-08-1500-planner.md).

## Local Test

Use the packaged ZIP, not the source-code ZIP. Close the game before replacing:

```text
%LOCALAPPDATA%\Whiskerwood\Saved\mods\WorkerOptimizer\
  WorkerOptimizer.pak
  WorkerOptimizer.uplugin
```

Load only one Worker Optimizer copy, local or Workshop. Use a separate save,
preferably at night or just after day start. Record actual assignments, protected
workers, reserve and total click-to-completion duration. Check that the icon is
visible only in the gameplay layer and that hiding it does not restart or cancel
a running request. Package checks do not establish live assignment success or
compatibility with other mods.
